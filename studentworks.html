BONUS 01 / AI COLLABORATION LOG

AI 協作紀錄與使用反思

本專區用來說明 AI 如何協助網站架構、文案、前端樣式與檢查清單。請保留與 AI 的真實對話截圖，依教師規定作為佐證。

協作流程紀錄

階段一｜規劃網站架構

提示詞摘要：依系所網站評分規則規劃 index.html、studentworks.html、graph 素材資料夾與兩頁互相導覽的資訊架構。

成果：建立首頁、學生作品頁與根目錄檔案架構；將主導覽、系所介紹、課程方向、作品集與頁尾資訊分區。

階段二｜產生樣式與互動

提示詞摘要：以深綠、米白、金色為視覺主色，設計專業、響應式的系所網站，並加入行動版導覽與作品分類篩選。

成果：新增手機版導覽、作品分類篩選、影音區塊及可讀性改善；圖片使用 graph/ 相對路徑。

階段三｜檢查上線與加分要求

提示詞摘要：依評分表確認檔名、相對路徑、兩頁連結、AI 使用說明、GitHub Pages 操作與 Commit 紀錄。

成果：加入部署指南、素材來源與授權紀錄、雲端修改步驟。正式上線和 GitHub Commit 仍須由專案擁有者實際執行。

使用心得與人工查核

AI 能協助快速建立網站初稿，但輸出不會自動代表校方事實，也不能取代瀏覽器測試、素材授權確認或真實 GitHub 發布驗證。

  • 逐一確認檔名大小寫、HTML 連結與圖片／影片相對路徑。
  • 將「示範課程方向」和「校方正式公告」清楚區分。
  • 將影片與圖像素材留在 graph/，避免引用本機絕對路徑。
  • 正式加入真人照片或作品前，確認著作權及影像使用同意。
  • 上線後用桌機與手機實際開啟頁面並檢查影音是否播放。

建議截圖存證

請截取 AI 討論架構、排除路徑錯誤、生成版面與規劃加分區塊的真實對話。不要把本頁整理摘要冒充成逐字對話紀錄。

BONUS 02 / CLOUD VERSION CONTROL

GitHub 雲端修改與版本紀錄

這是額外加分的執行紀錄區。要獲得版本控制項目的證明，必須在你自己的 GitHub Repository 完成一次線上編輯並提交 Commit。

待完成：需實際上傳後操作

GitHub 線上編輯流程

  1. 打開自己的 Public Repository，確認首頁檔案是根目錄的 index.html。
  2. 點開 index.html，再點右上方鉛筆圖示（Edit this file）。
  3. 微調一段文字，例如把首頁副標題換成自己的學習理念；不要刪除 HTML 標籤。
  4. 點選 Commit changes，寫下修改摘要，再確認提交。
  5. 到 Settings → Pages 取得公開網址，重新整理網站並確認修改已發布。
開啟 GitHub ↗　GitHub Pages 說明 ↗

提交紀錄填寫表

請在操作成功後，把實際資料填入作業報告或下方紀錄；不要先填寫虛構的 Commit SHA 或日期。

Repository 網址：完成上傳後填入
Commit 日期：填入實際提交日期
Commit 摘要：例如「Update homepage introduction」
Commit SHA：從 GitHub Commit 歷史複製實際短碼
發布網址：填入 Settings → Pages 顯示的網址
建議提交訊息：Update homepage copy and verify Pages deployment

加分佐證建議：截圖顯示 Repository、Commit 訊息及已開啟的公開網站，並確認這三者對應同一個專案。
